# 领域文档

本仓库采用 single-context 领域文档布局。工程技能在理解代码和规划变更前，按照本文件读取领域说明和架构决策。

领域文档及 ADR 使用简体中文；代码标识、命令、路径、API 名和行业通用技术术语保留原文。

## 开始了解代码前读取

- 仓库根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作相关的 ADR

若这些文件不存在，继续当前工作，无需报告缺失，也不要提前建议创建。`/domain-modeling` 会在领域术语或架构决策得到确认后创建相应文件。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-示例决策.md
│   └── 0002-另一项决策.md
└── packages/
```

## 使用术语表中的词汇

当 issue 标题、重构建议、假设或测试名称涉及领域概念时，使用 `CONTEXT.md` 中定义的术语，避免改用含义相近但未定义的名称。

若需要的概念不在术语表中，检查该术语是否确实属于本项目。确认存在领域词汇缺口时，记录下来交给 `/domain-modeling` 处理。

## 标明与 ADR 的冲突

若计划中的工作与现有 ADR 冲突，明确指出相关 ADR 和冲突内容，不要直接覆盖已有决策。
